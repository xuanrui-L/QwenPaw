角色一致性Master Cast Lineup：用卡司定妆照解决相对一致性问题

2026-07-27 · 针对 QwenPaw Creator 的视觉开发管线（VisualEntity / R2V / storyboard）

目标：在单角色 continuity 已经可控的基础上，建立跨角色相对一致性（relative consistency）锚点——一张 canonical 的 Master Cast Lineup（卡司定妆照），让多角色同框的分镜图与视频不会"各自为政"。

一、问题定义：什么是相对一致性

当前 Creator 通过 VisualEntity.continuity 与 VisualVariant 已经较好地解决了单角色绝对一致性：同一角色单独出现时，体型、脸型、肤色、发色、瞳色、标志性特征保持稳定。

但绝对一致不等于相对一致。当多个角色同框时，以下漂移会显著破坏成片观感：

  • 比例失调：角色 A 在单独立绘中很高，但与角色 B 同框时忽高忽矮。
  • 风格错位：角色 A 偏写实，角色 B 偏三渲二，角色 C 像插画，像三个不同片源剪在一起。
  • 年龄/时代感冲突：同一部古装短剧，某角色服装像汉唐，另一角色像民国。
  • 色调/肤色冲突：冷暖基调、肤色饱和度在同一画面里不统一。
  • 站位/遮挡歧义：模型不清楚角色之间的默认空间关系，导致关键帧中角色被错误遮挡或面朝方向矛盾。
根因：没有跨角色的 canonical 锚点。 当前 R2VCreation 只持有 character_refs 列表和各自的 selected_artifact_version_id；分镜/视频生成时参考的是零散的个体锚点图，模型在像素层面从未同时"见过"所有角色站在一起的样子。

1.1 代码现状佐证

  • backend/services/project_files/models.py::VisualEntity 只描述单个实体，VisualDevelopment 是扁平 entities 集合，没有 cast/lineup 概念。
  • R2VCreation 的 storyboard_reference_version_ids / video_reference_version_ids 由 LLM 或执行层逐元素拼装，缺少"当角色数 ≥2 时必须先有群体定妆照"的强制规则。
  • visual_development_agent.system.txt 强调个体身份参考图与变体一致，但未要求生成包含多个角色的同帧参考图。

二、设计原则

引入 Master Cast Lineup：一张包含全部（或主要）角色的定妆照，作为跨角色相对一致性的"视觉宪法"。

角色 A 单独立绘
→
角色 B 单独立绘
→
Master Cast Lineup
同框定妆照
→
分镜图
→
视频

Lineup 需要同时锁定以下五个相对维度：

维度Lineup 中必须表达的内容
Scale Ratio角色之间的身高、头身比、体型差异（用并排站立展示）。
Style Baseline统一的渲染风格、画质、笔触/材质基线。
Color Palette肤色、发色、服装色、整体冷暖调子在同一光照下呈现。
Era / Vibe古装/现代/科幻等时代元素在同一画面中兼容。
Spatial Order默认站位、朝向、前后关系，为后续分镜提供空间基准。
关键决策： Lineup 只解决"角色同框时彼此像同一片子"的问题；单角色的表情、动作、服装细节仍由各自的 VisualEntity 与 Variant 负责。Lineup 不替代个体锚点，而是作为群体锚点被优先引用。

2.3 风格一致性方案（debate）

Master Cast Lineup 主要解决角色之间的相对一致性（谁比谁高、谁和谁像同一片子）。但"像同一片子"还有另一半——风格一致性（渲染方式、色调、材质、时代感）。这里给出几种处理路径的权衡：

方案做法优点缺点推荐阶段
A. 文本 + Lineup 兜底
（当前方案）		靠 visual_bible/style 文本约束 + Lineup 作为风格参考图。零新增 schema，直接复用本方案。风格是隐式的；Lineup 生成失败或被跳过时，风格约束只剩文本，易漂移。P0
B. Style Reference Board新增 VisualStyleBoard 实体，生成 1~4 张风格/色调/材质参考图，自动注入所有视觉生成链最前面。风格锚点显式化、可复用、可质检；减少 Lineup 负担。新增 schema/pipeline/UI；多占参考图槽位；增加一次生成成本。P1
C. 模型级风格提示注入扩展 video_capabilities.py / image_model_prompt_guidance()，按模型族注入风格控制词典。无 schema 改动，成本低。纯文本约束，无法替代参考图；对抽象风格（“王家卫式”）效果有限。P0/P1
D. B + CStyle Board 作为参考图 + 动态风格提示词作为文本补充。约束最强，适合高风格化项目。改动最大、成本最高。P2
推荐： 本方案 P0 先走 A + C：用现有 visual_bible/style + Lineup 参考图 + 模型感知提示词注入兜底。数据模型为 B 预留扩展位（例如 VisualDevelopment.style_boards），并在监控或人工反馈中发现风格漂移时，P1 引入 Style Reference Board。

2.4 变体一致性：同一角色的不同造型如何不漂移

相对一致性还有一个容易被忽略的维度：角色内部变体（intra-character variant）一致性。同一个 VisualEntity 下可能有多个 VisualVariant：不同服装、不同年龄阶段、甚至不同风格（如下图中的 nba-master / nba-rookie / shaolin-trainee）。如果没有 canonical 锚点，新变体很容易在脸型、肤色、头身比、风格上偏离原有设定。

核心方案：Canonical Variant（标准变体）

  • 每个 VisualEntity 指定一个 canonical_variant_id，作为该角色身份的"母版"。
  • 生成任何新变体时，默认以 canonical variant 的 selected_artifact_version_id 作为首要参考图，prompt 必须声明"与参考图为同一角色，仅改变 X"。
  • continuity 中声明的核心身份特征（脸型、肤色、发色、瞳色、身高范围等）禁止在新变体中改变；若用户确实需要改变这些特征，应新建 VisualEntity 而不是新建 Variant。
  • 允许在变体间变化的属性应限制在白名单内：服装、发型、配饰、年龄化妆、光影、场景。

数据模型改动

class VisualEntity(StrictModel):
    ...
    canonical_variant_id: EntityId | None = None


class VisualVariant(StrictModel):
    ...
    # 显式声明该变体从哪个变体派生（可选，用于血缘追踪）
    derived_from_variant_id: EntityId | None = None
    # 标记变体差异类型，例如 costume_change / age_stage / alternate_style
    consistency_tags: list[str] = Field(default_factory=list)

管线与 Prompt 规则

  1. 参考图强制注入：在 image_execution.py 中，当生成目标为已有 VisualEntity 的新 Variant 时，自动把 canonical variant 的 selected artifact 加入 reference_artifact_version_ids 首位。
  2. Prompt 规则写入 visual_development_agent.system.txt：
    • 所有新 Variant 必须以 canonical variant 的 selected_artifact_version_id 为首要参考。
    • 不得改变 continuity 中声明的核心身份特征；若用户要求改变，必须新建 VisualEntity。
    • Variant 的 prompt 必须明确写出"同一角色，仅 X 不同"。
  3. VLM 一致性质检：新 Variant 生成后，用 VLM 与 canonical variant 做对比，检查脸型、肤色、头身比、标志性特征是否一致；失败则返回 retry 原因。
  4. Master Cast Lineup 的衔接：Lineup 默认使用每个角色的 canonical variant；若某场景需要非 canonical variant（如角色换装后同框），则生成该场景专用的 sub-lineup。

UI 改动

  • 在 AssetsPage 的 Variant 卡片上显示"Canonical"徽章。
  • Variant 详情页提供"与 Canonical 对比"的左右视图，高亮差异区域。
  • 生成新 Variant 时，若未引用 canonical artifact，给出警告。

  • character_refs 中每个 ID 必须存在于 visual.entities 且 kind == "character"。

  • selected_artifact_version_id 必须存在于 assets.artifact_versions_by_id。

4.2 Lineup Prompt 模板

主体：全员卡司并排站立定妆照，从左到右依次为 {names}。
布局：全身像，正面或 3/4 侧面，双脚着地，角色之间留有清晰间隙。
比例：{relative_notes}。
环境：纯色或极简中性背景，避免复杂场景干扰角色识别。
风格：{visual_bible} + {style}，统一渲染风格与画质。
约束：无文字、无标签、无网格线、无 UI 元素；每个角色面部清晰可辨。

严格遵守 PR-A "prompt discipline"：Lineup 作为设定图，画面中不能出现文字、编号、宫格线。

4.3 自动注入参考链

在 image_execution.py::GENERATE_STORYBOARD_IMAGE 与 r2v_execution.py 中增加 helper：

def _resolve_cast_lineup_refs(project, creation):
    refs = []
    for lineup_id in creation.cast_lineup_refs or []:
        lineup = project.visual.cast_lineups.items.get(lineup_id)
        if lineup and lineup.selected_artifact_version_id:
            refs.append(lineup.selected_artifact_version_id)
    # 未显式绑定但包含 ≥2 角色时，自动匹配覆盖这些角色的 lineup
    if not refs and len(creation.character_refs) >= 2:
        refs = _auto_match_lineups(project, creation.character_refs)
    return dedupe(refs)

4.4 变体生成管线

  1. 生成新 Variant 前，若 VisualEntity.canonical_variant_id 已设置，自动把 canonical variant 的 selected_artifact_version_id 加入参考图首位。
  2. 生成完成后，VLM 对比 canonical variant 与新 Variant，检查核心身份特征。
  3. 若用户要求改变 continuity 中声明的核心特征，拒绝并提示新建 VisualEntity。

4.5 Prompt 体系升级

在 visual_development_agent.system.txt 新增章节 相对一致性与卡司定妆照：

  • 当 Project 包含 2 个及以上常驻角色时，必须先建立或更新 Master Cast Lineup，再进入分镜图生成。
  • Lineup 必须使用每个角色的 selected_artifact_version_id 作为参考；禁止凭空重新描述角色外观。
  • 同一片子的所有 Lineup 必须共享同一风格基线与色调；不同 Lineup 之间角色比例必须一致。
  • Lineup 作为设定图必须无文字、无网格线、一图一变体。
  • 生成新 Variant 时必须以 canonical variant 为首要参考，不得改变 continuity 中的核心身份特征。

同步更新 r2v_generation_director.system.txt：多角色分镜/视频 prompt 必须显式引用 Lineup（如 "图1 是卡司定妆照，图2 是本镜分镜图……"），并强调角色站位、遮挡、朝向与 Lineup 保持一致。

五、分镜级人物对比图（Shot Cast Sheet）

5.1 它是不是 sketch？

默认是 sketch/轻量设定稿。 项目级 Master Cast Lineup 是全彩 canonical 定妆照；分镜级对比图只需要让当前 shot 出现的几个角色在同一画面里被快速比对，因此默认用速写/线稿/低完成度风格即可——生成更快、迭代成本更低，也不易与最终分镜图争夺视觉焦点。

当 shot 有特殊视觉要求（如特写、特殊光影）时，可切换为与项目风格对齐的轻渲染版本，但画面中仍不允许出现文字、编号、宫格线。

5.4 管线改动

  1. 触发时机：当 R2VCreation 包含 ≥2 个角色且 generate_shot_cast_comparisons=True 时，在生成分镜图之前为每个 shot 生成对比图。

八、验收标准

  • 任意包含 2 个及以上常驻角色的 Project，Agent 能生成至少一个 VisualCastLineup，且 selected_artifact_version_id 指向有效 image artifact。
  • Lineup 图片中无文字、无宫格线、无 UI 元素（人工/VLM 抽检）。
  • 多角色 R2V Element 的 storyboard_reference_version_ids 首位或前几位包含 Lineup artifact version。
  • 视频生成参考列表中，Lineup 出现在 storyboard 之后、角色锚点之前。
  • 开启 shot 级对比图后，每个多角色 shot 都生成 shot_cast_comparison_version_id，并出现在对应 storyboard 的参考列表中。
  • Shot 级对比图默认无文字、无宫格线；风格为 sketch/轻量设定稿。
  • 同一角色新增 Variant 时，核心身份特征（continuity 覆盖字段）与 canonical variant 一致；VLM 质检通过。
  • Prompt 文件 sha256 引脚已更新，相关单元测试与 pre-commit 检查通过。
  • E2E：创建 3 角色短剧，验证从角色锚点 → Lineup → 分镜级对比图 → 分镜 → 视频的参考链完整，且 Lineup 出现在分镜/视频请求中。
非目标： Lineup 不解决动作一致性、表情一致性、口型一致性；这些问题仍由现有 continuity、shot 描述与声音公式负责。本方案聚焦"同框时彼此像同一片子"的相对一致。
