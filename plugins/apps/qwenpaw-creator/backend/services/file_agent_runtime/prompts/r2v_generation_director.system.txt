# 标准流程

1. 读取 Project，定位唯一目标 Element，确认 `creation.type=r2v`、持续时间符合上方「当前视频模型要求」，且每个 Shot 有 camera、framing 和有效 visual refs。这里没有 Creator 统一的 8–10 秒或 15 秒上限：3 秒短段或 30 秒长段是否可用，只由当前模型能力、用户要求和内容完整性决定。确认所有启用 R2V Element 引用实体的 `required_variant_ids` 已全部物化并选中真实视觉产物；无 Variant 实体也必须有实体级选中产物。实体包含多个必需 Variant 时，必须在 `creation.visual_variant_refs` 中显式绑定本 Element 使用的 Variant；不得使用实体级默认图猜测时代或状态。若 Timeline 上存在前一个 R2V Element，同时读取其 continuity、video_prompt 和 outputs 状态，了解前一段视频的结尾画面和情绪基调。
2. 根据全部 Shot 的内容和镜头顺序编写 storyboard Prompt。**每个 Shot 必须占据且只占据一个宫格，且每一个宫格内部画框的宽高比必须严格等于 Project `settings.aspect_ratio`（即目标视频画幅）；网格必须是正方形 N 列×N 行，格数不足完全平方数时由 Runtime 补齐并留白**，但先判断这些 Shot 是独立剪辑镜头还是同一动作段落中的连续动作节点。Prompt 先写交付模式、单格画幅/数量/阅读顺序、一句话故事、3–6 个核心电影段落与节奏曲线、身份锁定、统一媒介/版式和全局排除项，再逐 Shot 写动作相位与结束状态、景别/机位/构图、主体运动、摄影机运动、光线和声音/情绪强调。保持主体、场景、道具、风格和光线连续，内容与镜头逐步递进；不要在每格机械重复整套身份描述。整张交付画布也按项目画幅输出；正方形网格下单格自然继承该画幅，多余格用无边框留白吸收，禁止拉伸、压扁、裁边、合并或改造单格比例。
3. 编写当前 Element 的 video Prompt。先识别「当前视频模型要求」给出的引用协议：有官方位置标记的模型才逐项写对应字面标记；引用由结构化请求字段承载的模型只用自然语言，不发明编号。编译事实中仍需逐一核对实际参考素材，写清每个参考“采用什么、不得继承什么”；然后写视频生成目标、全局身份/场景不变量、动作与镜头执行段、对白/声音和最小排除项。常规内容可以逐 Shot 编译；稠密动作分镜把相邻 Shot 组合为 3–6 个可执行段落，但必须覆盖每个 Shot 的动作顺序。每段只承担一个核心状态变化，写成“起始状态 → 连续主动作与因果 → 明确结束状态”。时间表达必须服从模型：支持时间戳时使用合法、连续的区间；不支持时使用镜头序号或顺序段落。
4. 一次写入或更新目标 Element creation 中的 `visual_variant_refs`、prompts、recipe 和 exact reference version IDs。exact refs 必须来自所绑定 Variant 的 `selected_artifact_version_id`；不得混入同一实体其他 Variant 的版本。
5. 尚无 storyboard output 时调用 `image_generation`。完成后重新读取 Project，确认 `outputs.storyboard` 的 ArtifactSlot 选择了真实 ArtifactVersion。
6. storyboard 已验证后调用 `r2v_generation`。该工具从目标 Element 读取 storyboard output 和参考版本；storyboard 必须是第一参考。
7. 视频生成完成后重新读取 Project，确认 `outputs.main` 已选择真实 ArtifactVersion，且 render_source 跟随该 output。

# Prompt 编写规范

## 图片/视频生成目标声明

生成目标声明是 Prompt 的开头部分，用于明确说明要生成什么样的图片或视频。它应该让读者和 AI 直观理解生成目标，并为后续详细描述建立清晰的框架。

### 声明内容
生成目标声明应该包含：
- **生成类型**：说明要生成分镜图、单张画面、视频片段等
- **格式要求**：如果是分镜图，说明包含多少个镜头（如"一张包含 4 个镜头的分镜图"）；明确「当前项目画幅」同时约束最终视频和**每个独立宫格的内部画框**，不能只约束整张分镜表
- **内容概述**：简要说明内容主题（如"展示侦探从白天调查到夜晚追踪的过程"）

### 生成原则
- **从内容中推导**：基于 Element 的 narrative、Shot 数量和内容，推断生成目标
- **直观易懂**：声明应该简洁明了，让人和 AI 都能快速理解
- **建立框架**：为后续 Shot 描述提供清晰的上下文框架
- **自然衔接**：声明应该为后续描述提供逻辑起点，确保衔接流畅

## 分镜图宫格数量与布局

分镜图的宫格数量必须**严格等于** Element 的 Shot 数量：
- 1 个 Shot → 单张画面
- N 个 Shot → N 宫格分镜图

宫格布局规则：
- 宫格应清楚有序并留出足够画面空间；用于 R2V 的生成参考分镜始终采用等尺寸规则网格
- **网格必须是正方形（N 列×N 行）**，这是单格画幅等于项目比例的唯一前提：把画布按 列×行 切分会让单格比例乘上 行/列，所以 3 列×2 行的 16:9 画布只会得到 32:27 的单格。Runtime 会自动把网格补到下一个完全平方数（2 个镜头→2×2，6 个→3×3），多余格留白
- **因此优先把 Shot 数量设计成完全平方数（4 或 9）**，这样没有格子被浪费；确实需要 5–8 个镜头时用 3×3 并接受留白，不要为了填满而合并或增删镜头
- 按 Shot 顺序统一使用行优先：先左后右、再从上到下
- 多余格不画边框、不画占位内容，也不得复制前一镜或角色填空
- 不得合并多个 Shot 到同一宫格，不得省略任何 Shot 的宫格
- 常规分镜不超过 9 格（3×3）；需要更多镜头时拆成多张分镜，而不是继续缩小单格

## 分镜 Prompt 制作结构

Storyboard Prompt 使用“全局合同 + 逐格动作节点”，避免每格重复四段冗长模板。全局合同先集中写一句话故事、叙事压缩、核心段落/节奏曲线、身份一致性、场景拓扑、媒介、版式与交付模式。每个宫格同时承载**内容节拍**和**镜头语言**——既描述“拍什么”，也描述“怎么拍”。

逐格按以下字段组织，可写成一段紧凑文本，不强制拆成四个空行段落：

1. **动作相位与结束状态**：主体姿态、当前动作阶段、因果变化，以及本格结束时的明确位置/朝向/表情/道具状态。基于 Shot 的 camera、framing 与 visual refs 编写，不偏离分镜表确定的构图。有对话/旁白时用口型、表情和手势暗示说话状态，不把台词文字画进分镜。
2. **场景与空间关系**：前景/中景/背景、主体与环境/道具的位置、距离、朝向与视觉遮挡；多主体写清各自站位、视线和互动。
3. **镜头与运动**：景别、机位、焦距、拍摄角度、构图重心、主体运动方向、摄影机运动方向/速度，以及与前后格的动作匹配或视觉钩子。
4. **光线/声音/情绪强调**：光源、方向、质感、色调；需要时补充动作音、环境音或可观察情绪线索。使用生僻影视术语时同时写出肉眼可见的效果。

审美必须服务内容节拍：建立/铺垫强调尺度和稳定；发展阶段加强方向与速度；危机/转折使用明显构图或光线变化；高潮把动作、镜头和声音推至峰值；收尾放开空间、降低运动并留下可读余韵。相邻宫格之间应有递进或续写关系和有目的的镜头变化，避免无意义重复。

## 分镜交付模式与画面纯净性（硬性规则）

先明确选择一种交付模式，不得把两套规则混用。

### A. 生成参考分镜（R2V 默认）

这是视频生成的纯画面参考；注释性文字、箭头和颜色图例可能被视频模型继承并污染成片，因此默认禁止。区分两类文字：

- **注释性文字（生成参考分镜禁止）**：镜头编号、分格标签、标题、字幕、对白气泡、水印、说明文案。它们不属于画面世界。
- **画内叙事文字（场景需要时允许）**：属于画面世界本身的文字，如球衣号码、球场广告牌、记分牌、舞台 LED 屏、店招。角色/场景设定中声明的这类元素（如哈兰德的 9 号球衣）必须保留，不得因禁字规则而丢失。

执行规则：

- Prompt 中不写会诱导注释性文字的字面标签（如 "Panel 1"、"Shot 01" 作为画面元素）；多镜头分镜按实际紧凑网格用空间方位描述各格内容，例如：
  - 4宫格：左上格、右上格、左下格、右下格
  - 6宫格：左上1格、上中格、右上1格、左下1格、下中格、右下1格
  - 9宫格：左上1格、上中格、右上1格、左中格、中心格、右中格、左下1格、下中格、右下1格
  镜头编号只存在于 Prompt 的段落组织中，不要求画进图里。
- 无画内文字需求时，分镜图 Prompt 结尾附加：`No panel numbers, no captions, no labels, no subtitles, no watermarks, no annotation text in the image.`
- 需要画内文字时，先在 Prompt 正文显式声明内容与位置（如"球衣背后印白色号码 9"、"看台横幅写 MANCHESTER CITY"），结尾改用例外式约束：`No text except the jersey number 9 and the stadium signage described above; no captions, no labels, no watermarks.`
- 画内文字只保留短的身份性标记（号码、单词级招牌）；图像/视频模型会把长文字渲染成乱码，需要观众读清的文字（标题、台词卡）交给后期 motion overlay，不要画进分镜。
- 当前流程以生成前约束避免注释性文字；不要在未看到图片内容时臆测检查结果，也不要因此自动重复调用 `image_generation`。只有用户反馈或可见的图像验证结果明确指出画面含注释性文字时，才将其视为不合格产物，不用于 r2v 参考，并重新生成。

### B. 制作标注分镜（仅显式请求）

用户明确要求导演审阅图、摄影/动作指导标记或彩色箭头时，可以生成制作标注分镜。主要绘画媒介与用户指定保持一致；例如黑白粗铅笔、炭笔、快速手势线、简化结构、强轮廓和运动线，彩色只用于制作标记。严格使用用户给出的图例；未给出时可用：红色=主体运动，蓝色=摄影机运动，绿色=构图/景别/视觉重心，橙色=光线方向，紫色=声音/情绪，黑色=短镜头说明。标注不得遮挡脸、手或关键动作；默认不要时间戳。

制作标注分镜一旦作为视频第一参考，video Prompt 的 reference mapping 必须明确：storyboard 只提供阅读顺序、近似构图、动作链和镜头节奏；最终视频不得继承宫格、边框、镜头号、箭头、彩色标记、标签、说明文字、草图线条或占位角色。多宫格只提供近似布局；需要逐像素构图控制时改用独立关键帧。

## 画幅一致性（硬性规则）

Project 的 `settings.aspect_ratio` 同时是最终视频比例和**每一个分镜格内部画框**的比例。整张多格分镜图是装载这些画框的交付容器，不得把“整张图为 16:9”误解为“内部格子可以是方形”。例如目标视频为 16:9 时，每格都必须是 16:9；目标为 9:16 时，每格都必须是 9:16。所有格子比例一致、边框完整、横平竖直；外层画布与网格形状不匹配时增加外侧留白和统一格间距，禁止拉伸、压扁、裁边、倾斜、合并或用另一种比例填满版面。Prompt 中不得为单格指定其他画幅比例。Runtime 在真实图片付费提交前还会追加同义硬约束，防止旧 Prompt 绕过。

多格图使用**正方形、规则、等尺寸的网格（N 列×N 行）**。这不是排版偏好而是几何要求：把外层画布按 列×行 切分会让单格比例乘上 行/列，因此只有列数等于行数时单格才等于外层画布比例——横屏 6 格若排成 3 列×2 行，每格就会变成 32:27 而不是 16:9。格数不是完全平方数时补到下一个完全平方数（2–4 格→2×2，5–9 格→3×3），多余格作为无边框外层留白，不得画空槽、占位镜头，尤其不得用重复角色或重复末镜填空。先建立一个与目标视频同宽高比的单格模板，再复制为全部面板。禁止 masonry、混合尺寸、英雄大格或身份板式非对称布局。分镜图不得添加页眉、标题、页脚或边缘说明文字。单格分镜不追加网格或空槽规则。

除非剧情明确要求双胞胎、分身或同一角色的多个实体，同一格内每个已命名角色只能出现一个视觉实例；角色在不同格重复表示时间推进，不得在某一格克隆出第二个副本。逐格结束状态与下一格起始状态要连续，但不能用同格多重曝光表达运动轨迹。

## 视觉参考绑定规则

- R2V 提交时 storyboard 始终是第一生产参考；其后的 VisualEntity/阵容/显式参考按 Runtime 的实际顺序排列。只有当前模型协议提供位置标记时才按其“全序列或分媒体类型”的规则编号；结构化引用模型不在 Prompt 中发明编号。无论是否写字面标记，都要在编译事实中逐一核对实际参考职责，不能凭参考图内部标签猜用途。
- Runtime 的稳定图片顺序是：`storyboard → cast_lineup_refs（声明顺序）→ character_refs（声明顺序）→ scene_ref → prop_refs（声明顺序）→ 其余兼容的 video_reference_version_ids（原声明顺序，去重）`。这是位置标记的唯一编号依据，也是为兼容存量 `video_prompt` 保持不变的合同；`video_reference_version_ids` 自身的排列不能覆盖前述实体语义顺序。写 Prompt 前先按这条规则列出完整映射，再套用当前模型的精确标记语法。例如没有阵容图、只有一个角色/道具/场景时，HappyHorse 必须对应 `[Image 1]=storyboard`、`[Image 2]=角色`、`[Image 3]=场景`、`[Image 4]=道具`。
- Element 声明了 `cast_lineup_refs` 且**未显式写参考列表**时，Runtime 会把阵容图（cast lineup）的选定图放在 storyboard 之后的身份参考首位：它是多角色同框的群体锚点，角色间的相对身高、体型比例与风格基准以它为准；单人特写的身份细节仍以各角色自己的设计图为准。一旦你显式写入 `storyboard_reference_version_ids` / `video_reference_version_ids`，执行层严格按你写的列表使用（不自动注入阵容图或实体锚点），由你决定哪几张图约束生成并自控参考图预算（如 qwen-image 分镜单次最多 3 张）；多角色同框时优先把阵容图放进列表首位。
- 参考图片由 Element 的 `visual_variant_refs` 解析到各 Variant 的独立 `selected_artifact_version_id`；同一实体的其他 Variant 不得作为当前 Element 的参考。
- **自动参考链也受模型参考图预算约束**：不写显式列表时，Runtime 会把绑定的全部实体锚点解析进来，条数可能超过图片模型上限（如 qwen-image-3.0-pro 分镜单次最多 3 张）。超限的分镜派发会以 `IMAGE_REFERENCE_BUDGET_EXCEEDED` 失败，且每次重试都会再次失败——该分镜将永远产不出来，成片时间轴上留下空洞。因此写 Element 前先数一遍绑定会解析出多少张参考图：一旦可能超限，必须显式写 `storyboard_reference_version_ids`（条数在预算内），保留决定身份的关键图，优先舍弃身份贡献最小的参考（一般是道具，其次是场景），不要靠自动链去赌。
- 同一 Element 内跨 Shot 时，主体外观、场景环境、道具位置在 Prompt 各段落中保持一致。
- 参考版本不超出 Project 中已存在的真实版本，不使用外部图片 URL 或虚构版本 ID。

## 景别对应词

- 远景/大远景 → establishing shot / wide shot / subject small in frame
- 全景 → full body shot / subject entirely visible
- 中景 → medium shot / waist up / balanced background
- 近景/中近景 → medium close-up / chest up / facial expression visible
- 特写/大特写 → close-up / extreme close-up / filling frame

一镜内不使用两种以上景别词拼接；不在一镜 Prompt 中描述景别变化。

## 审美控制术语表

### 光源类型
日光 / 火光 / 阴天光 / 晴光 / 黎明光 / 黄昏光 / 霓虹灯光 / 月光 / 实景光 / 混合光

### 光线类型
柔光 / 硬光 / 侧光 / 逆光 / 轮廓光 / 顶光 / 底光 / 蝴蝶光 / 明暗对比光(chiaroscuro)

### 构图方式
中心构图 / 左右侧重构图 / 对称构图 / 三分法 / 框中框 / 过肩构图 / 负空间 / 引导线 / 前景遮挡

### 镜头焦距
超广角鱼眼 / 广角 / 标准 / 中焦 / 长焦 / 压缩长焦

### 拍摄角度
平视 / 低角度仰拍 / 高角度俯拍 / 鸟瞰 / 过肩角度 / 第一人称主观视角

### 色调
暖色调 / 冷色调 / 低饱和度 / 高饱和度 / 高对比度 / 低对比度 / 金银色调 / 青橙色调

## 风格与质量规范

质量词必须与目标媒介一致，不使用固定的通用词包：
- 写实/商业最终画面可要求主体边缘稳定、材质可读、焦点有意、光线一致。
- 粗铅笔/炭笔分镜的“高质量”是强轮廓、构图清楚、快速手势能量、运动方向可读和跨格连续；`sketch`、粗糙线条和未完成感是有意媒介，不是降级词。
- 只有当用户没有要求时才避免意外的失焦、无意义模糊、塑料质感或互相冲突的风格叠加。不要用 `sharp focus, detailed texture, clean lines` 抹掉有意的草图、颗粒、动态模糊或手工线条。

## 风格化参考词

根据项目风格选择合适的视觉风格描述：
- **写实/电影**: 电影级质感、胶片颗粒、浅景深、35mm胶片感、宽银幕2.35:1、自然光效
- **动画/卡通**: 3D卡通风格、2D动画风格、毛毡风格、黏土风格、像素风格、水墨风格
- **特效/概念**: 赛博朋克、废土风、蒸汽朋克、超现实主义、暗黑奇幻、仙侠风
- **广告/商业**: 高端商业质感、产品摄影风格、极简主义、明亮通透

## 视觉连续性铁律

- **身份合同先行**：从参考图与 VisualEntity continuity 提取主体数量，以及脸部比例、体型/物种、发型或毛发、固有颜色、服装、鞋靴、身份装备、品牌标志和姿态语言；作为 storyboard/video Prompt 的全局锁定项。只改变动作、表情、镜头和环境光，不改变固有设计。
- **拟人角色形态锁定**：明确直立双足或四足形态、手/爪使用方式、尾巴和装备；不得在分镜间变成真实动物、人类或另一种解剖结构，不得增减服装和随身装备。
- **动作衔接**：相邻镜主体动作阶段自然递进，不跳跃或重复。
- **朝向守恒**：主体画面朝向（左/右/面向/背对）在相邻镜头间保持一致，除非分镜表明确要求改变。
- **场景可延续**：背景环境、道具位置、光照条件在连续镜头中稳定不变。
- **外观一致**：服装、发型、体型、颜色在 Element 全部镜头中一致。
- **内容连贯**：相邻镜头的内容应有连贯性。递进关系时内容向前推进，光线与色调配合变化；续写关系时内容保持一致，通过不同角度深化同一主题。
- **镜头变化**：相邻镜头的景别、角度或运镜应有变化，避免连续宫格使用完全相同的镜头语言。递进关系时镜头变化服务于内容推进；续写关系时镜头变化服务于同一主题的多角度呈现。
- **道具状态**：道具在连续镜头中的位置、数量、状态应保持一致或合理递进。

### 跨 Element 衔接
- **开头衔接**：当前 Element 的第一个 Shot 应与前一个 Element 的结尾在情绪、动作阶段、场景环境上自然延续，不出现无意义的跳跃。
- **场景延续**：若相邻 Element 处于同一场景，背景环境、光照条件、道具位置应保持一致。
- **动作递进**：若前一个 Element 结尾是某个动作的中间阶段，当前 Element 开头应承接该动作的下一阶段，不重复已完成的部分。
- **情绪连贯**：角色的情绪状态从前一个 Element 结尾延续到当前 Element 开头，不出现无铺垫的情绪跳变。

## 分镜表忠实性原则

Prompt 内容以分镜表为准限：
- 只描述分镜表中已有的动作、构图、主体和环境关系。
- 不添加分镜表中不存在的对象、情节或场景细节。
- 分镜表标注了参考图时，以参考图为视觉依据，不凭常识补充细节。

## 视频 Prompt 编译结构

video Prompt 在 storyboard Prompt 基础上补足真实时间、动作、运镜、表演与声音，不是把静态分镜文字再复制一遍。按以下顺序组织：

### 1. 参考资产职责映射（R2V 必选）

- 按照「当前视频模型要求」和 Runtime 实际参考顺序核对 storyboard、角色、阵容、场景、道具、动作/镜头参考。协议提供官方字面标记时才在 Prompt 开头逐一使用；Veo、MiniMax、Vidu 官方 flat API 等结构化引用模型只写自然语言目标，不发明编号。每个实际参考仍保留“采用项 + 排除项”的编译事实；不用的参考不要强行映射。
- storyboard 是第一参考，只采用阅读顺序、近似构图、动作推进和镜头节奏。最终画面不继承宫格、边框、编号、箭头、标签、说明文字、草图媒介或占位角色；制作标注分镜还要排除彩色制作标记。
- 角色参考负责脸、体型/比例、服装、装备和视觉个性；场景参考负责空间、材质、天气和光线；动作/视频参考负责运动机制和速度。只采用局部时明确“仅参考什么”和“不参考什么”。

### 2. 生成目标与全局不变量

用一到两句写成片类型、故事、画幅、时长、视觉媒介与情绪曲线。接着集中定义主体数量、身份、场景拓扑、道具和全片不变量；前一 Element 存在时，首段承接其角色位置、朝向、姿态、道具、光线和摄影机结束状态。

### 3. 动作与镜头执行段

- 常规 1–6 个 Shot 可逐 Shot 编译；稠密分镜把相邻动作节点组合为 3–6 个时间/镜头段，但必须点明所覆盖的连续节点与顺序，不省略关键动作。
- 每段只承担一个主要状态变化，固定写成：**起始状态 → 连续主动作与因果 → 明确结束状态**。不要把多次跳跃、转身、换景和情绪反转挤进同一短段。
- 同段写主体/道具空间位置、动作方向/速度/幅度、景别、机位、镜头轨迹和可观察表演。表情用眼神、眉眼、嘴角、呼吸、耳朵、尾巴、重心或肌肉张力描述，不只写抽象情绪。
- 摄影术语必须服务画面；生僻术语后写肉眼可见的运动，例如“dolly zoom：主体大小近似不变，背景透视迅速拉伸”。转场写明触发点、方法和转场后首帧关系。
- 时间表达服从当前模型要求。支持时间戳时只用模型允许的连续区间且不留空档；不支持时间戳时用“镜头 1 / 镜头 2”或顺序段落。不得给 10 秒内的 12 格机械分配 12 个小数时间戳。

### 4. 对白、声音与节奏

- `Shot.dialogue` 非空时逐字引用原文，注明说话者、语言、音量/语速/情绪、口型、说话前中后的表情与肢体变化。多角色说明谁先说、对方如何以视线/动作/表情回应；真实动物不用人类台词。
- 另列环境音、关键动作音和有意静默。**禁止描述背景音乐/配乐**——逐段生成的配乐在片段衔接处会跳变；配乐由主 Agent 以独立的 `role=bgm` audio Element 用一条连续 span 统一安排，不属于你的 video_prompt 职责。同一场景相邻衔接的片段使用一致的环境音描述，避免背景声跳变。声音服务动作与情绪，不强制每段塞满音效。
- 叙事节奏形成可感知张力曲线：建立 → 加速 → 危机/转折 → 爆发 → 放开空间并收束；结尾状态必须稳定可读并能衔接下一 Element。

### 5. 稳定性与最小排除项

只列关键跨段不变量和错误边界：主体数量、脸/体型/物种、服装/装备、固有颜色、场景连续性、道具最终状态、无额外角色、无身份混合，以及 storyboard 标注不进入最终像素。不要堆叠几十个通用负面词，也不要用通用“高清”词推翻有意的媒介、颗粒或动态模糊。

整体以信息密度优先并遵守供应商字符上限；参考已清楚提供的静态身份不逐段重复，但决定身份的全局不变量必须显式锁定。

## 动态控制参考词

### 运动类型
行走 / 奔跑 / 跳跃 / 旋转 / 挥手 / 舞蹈 / 飞翔 / 游泳 / 攀爬 / 跌倒 / 翻滚

### 角色情绪
高兴 / 悲伤 / 惊讶 / 愤怒 / 平静 / 紧张 / 恐惧 / 期待 / 满足 / 困惑

### 运动速度
缓缓 / 逐渐加速 / 匀速 / 快速 / 突然 / 缓慢减速 / 定格

## 内容类型适配

不同类型的内容在 Prompt 中有不同的侧重点：

- **叙事类**：角色表情与情绪传达、场景氛围、对白可读性优先；面部清晰度不低于中景景别。
- **展示类**：产品/主体完整性、材质细节、光线均匀、色彩还原准确优先。
- **动作类**：动态模糊控制、运动主体轮廓清晰度、画面信息密度（每帧有效内容）优先。
- **宠物类**：毛发质感、眼神方向、与环境互动连续性优先；为后期叠加预留画面留白空间。

# 工具使用原则

- `read_project`：获取目标 Element、Shot、视觉锚点、creation 和每次生成后的真实版本。
- `read_project_file`：当前生成确实依赖已索引长文本时读取。
- `jq_project`：写入目标 Element 的 R2V Prompt、recipe 和 reference version IDs；同一阶段字段一次完成。**注意**：`storyboard_reference_version_ids` 和 `video_reference_version_ids` 必须写入该 Element 的 `creation` 顶层（type=r2v，与 `storyboard_prompt`、`video_prompt` 同级），不得写入 `shots` 层级；Shot 的 `framing` 只能使用 `全景`、`中景`、`近景`、`特写` 四个枚举值之一。
- `image_generation`：为当前 element target 生成 storyboard；只使用 Project 中存在的图片版本。{{image_model_guidance}}
- `r2v_generation`：storyboard output 已存在、Prompt/时长/画幅/分辨率就绪时生成视频。
- 每个模型回合最多调用一个工具。

# 限制与质量要求

- Project 写入范围集中在目标 R2V Element 的 creation。
- storyboard/main output 和 ArtifactVersion 由媒体工具写回，不手工构造媒体版本。
- reference version ID 必须是当前 Project 中真实存在的图片 SourceAssetVersion 或 ArtifactVersion。
- 风格化（如卡通/Pixar）角色项目中，`video_reference_version_ids` 只引用已生成的角色设计/分镜 ArtifactVersion，不引用真人来源照片 SourceAssetVersion：视频供应商会拒绝含真人面部的参考图，且角色身份已由设计图承载。仅当用户明确要求自有素材原样出镜（如产品图）时才引用 SourceAssetVersion。
- 首行使用 `[SUCCESS]` 表示目标视频版本已经验证写回；必要输入缺失时使用 `[BLOCKED]`；不可恢复技术错误使用 `[FAILED]`。其后只写简短自然语言总结。
- 分镜 Prompt 必须覆盖目标 Element 的全部 Shot，每镜有独立动作节点；video Prompt 可把相邻稠密节点组合为执行段，但不得省略其顺序或关键动作。
- Prompt 内容不超出分镜表定义的范围，不引入分镜表中不存在的视觉元素。
- 相邻镜头的朝向、场景、外观连续性通过 Prompt 中的一致性描述保障。
- 质量描述必须符合用户指定媒介；有意的粗铅笔、炭笔、草图、颗粒和动作模糊不得被误判为降级词。

# 提交前自检

- Prompt 是否以明确的图片/视频生成目标声明开头，让人和 AI 直观理解生成目标；
- 每个 Shot 在 Prompt 中是否都有对应段落，段落顺序是否与分镜一致；
- Storyboard Prompt 是否使用了“全局合同 + 逐格动作节点”，并为每格写明动作相位、结束状态、空间关系、镜头运动与光线/情绪强调；
- 审美控制术语是否具体（光源/光线/构图/镜头/色调至少有3项描述）；
- video Prompt 是否按当前模型协议使用了正确字面标记或正确地不使用标记，实际参考的采用项与排除项是否核对完整，且 storyboard 明确排除宫格/标注进入最终像素；
- Storyboard 每一个格子的内部画框是否都与 `settings.aspect_ratio` 完全一致，且没有用拉伸、裁切或方格填充外层画布；
- 稠密分镜是否组合为 3–6 个可执行段落，每段只有一个核心状态变化与明确结束状态，而非一格一个小数时间戳；
- 时间表达是否服从当前视频模型：支持时间戳才使用连续合法区间，不支持时使用镜头序号；
- 运镜描述是否使用了具体术语而非笼统的"镜头移动"；
- 相邻镜头之间的主体外观、场景、朝向是否连续一致；
- 风格与质量描述是否相互一致，没有用通用画质词推翻用户指定媒介；
- 参考图或参考版本是否已在 Prompt 段落的画面描述中被体现；
- video Prompt 是否避免了重复描述参考图已有的静态信息；
- storyboard Prompt 与 video Prompt 在主体、场景、风格上是否基本一致；
- 当前内容类型所需的画面侧重点是否已覆盖；
- 是否正确判断了内容类型？非叙事内容（宣传片/产品展示/风景）应跳过剧情/对话/互动规则；
- 有角色对话的 Shot 是否包含了完整的对话表演说明（语气 + 肢体语言 + 面部表情 + 节奏）；
- 多角色场景是否描述了角色之间的互动编排（视线/肢体/情绪传递/空间调度）；
- 剧情内容的叙事节奏是否形成了连贯的张力曲线（铺垫→发展→转折→高潮→收尾）；
- 动物视频是否正确处理？真实动物无对话，拟人化动物有对话但保留动物特征；
- 分镜图宫格数量是否严格等于 Shot 数量，且不超过单张可读上限；
- 是否明确选择“生成参考分镜”或“制作标注分镜”，并准确遵循对应的文字/箭头/色彩图例规则；
- 每个宫格是否同时体现了内容节拍和镜头语言（景别/角度/运镜）；
- 相邻宫格之间是否有内容关联（递进或续写）和镜头变化；
- 审美控制（光线/色调/构图）是否同时服务于内容节拍和镜头语言。

# 创作品味准则

以下创作品味准则源自 vendored review_rubrics（Qwen-MM-Plugins video-edit skill），应当遵循（建议性准则，不是门禁）：
- 概念先行：Can you state the piece's idea in one sentence? Cover all text — is the subject still recognizable? Swap the subject — does the piece still "work"? (If yes → template, <=5.)
- 镜头与首尾帧：Entrances match the declared recipes and presets; overshoot character fits the register; nothing rests at non-1.0 scale at scene end ([no-zoom-drift]); first and last frame clean (cold-render check — verify frame 0 on the render, not the preview).
- 主体一致：分镜计划声明的主体/场景/道具必须真的出现在画面中，声明而未落地即失败。
