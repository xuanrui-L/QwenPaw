# 互动作品界面设计

先读剧本、视觉设定和用户逐页要求，选择一种与影片一致的视觉方向，再完成文案、布局和细节。保留用户明确指定的标题与按钮文案。这里只指导作品界面，不重写剧本、不触发视频重制。Agent 编写设计要求前通过 view_skill 读取本 Skill；HTML 生成服务也会加载全文。

若任务只是单个抉择动效，使用视觉方向、沉浸叠层与抉择 pattern，输出一个选择层；不要生成四页、标题或地图。完整作品页面任务才应用以下四页合同。

## 文案先于装饰

- `title_policy.source=user`：首页标题逐字使用 `title_policy.title`。`auto`：项目名只是创建时的占位名；若用户在创作要求或剧本中明确指定作品标题，沿用该标题，否则结合剧本拟定一个简练、有辨识度的作品标题，不复述制作指令或截取简介。Agent 收到用户明确命名/改名时同步维护 Project.name 和 name_source=user；未指定时保留 auto。
- 在 `data-bind="project.title"` 内直接写最终标题，在 `data-bind="project.synopsis"` 内写最终引导文案。不要留空等待宿主灌入项目简介；项目 description / brief 是创作上下文，可能包含全部结局。
- 副标题通常 20–50 个汉字：日常场景 + 意外或两难 + 对观众的邀请。例：“一条迟迟不敢发出的消息，让今晚变得不同。换作你，会按下发送吗？”只写观众开场已知的事，不点名隐藏人物、后续反转、选择结果、路线数或结局数。不机械照抄例句。
- 结局页标题固定为“结局”，写在 `data-bind="node.title"` 内。不要出现“结局 1”、A/B、好/坏结局编号、全结局收集率、共几个结局等信息。已到达结局的感受可呈现，不列其他结局；不用 `progress.endings`。

## 三种可选设计方向

按影片选一种，提炼色彩、空间、字重与一个标志性视觉元素，避免拼贴所有效果。

1. **当代电影片头**：大面积留白、偏轴排版、标题与一条短引导形成鲜明层级，细线与一个主色作为导航语言。适合现实、悬疑、情绪短片；避免满屏发光、粒子与厚重卡片。
2. **都市通信叙事**：用消息游标、时间标记或一条对话线暗示故事媒介，克制的中性背景配单一强调色。适合手机、社交和办公室故事；不要仿制整个聊天软件或堆叠聊天气泡解释剧情。
3. **温暖编辑式**：暖灰/墨色/低饱和强调色、舒展字距、清晰的网格与柔和过渡，适合生活、关系和轻喜剧；不要复古纸张装饰淹没视频。

现代感来自间距、比例、对齐和层级。用系统字体，标题 `clamp()` 自适应；最多两级阴影、一种强调色。主要按钮有明确实底，次要操作弱化但可见；至少 44px 点击区、清晰 focus-visible、足够文字对比。动效用于入场、选中反馈和状态切换（约 180–400ms），不用全部元素无限呼吸、跳动、虚线流动。提供 prefers-reduced-motion。

## 沉浸播放 pattern

播放页只保留视频、薄导航和抉择层。视频舞台占据剩余全部空间，不放进窄卡片，不在上下堆大标题和说明。桌面和手机都用最小导航高度，横屏高度不足时进一步收紧。

可按项目改写的结构关系：播放页 `display:flex;flex-direction:column;padding:0`；导航 `flex:0 0 auto`；舞台 `position:relative;flex:1;min-height:0;min-width:0`；视频 `position:absolute;inset:0;width:100%;height:100%;object-fit:contain`；交互容器 `position:absolute;inset:0`。视频保持完整画幅，留边跟随影片颜色。不要固定 55% 高度、宽高上限或周围巨大的装饰边框。

背景以当前片段画面的低亮度底色为主，视觉设定为无画面时的后备；宿主会从真实视频采样 `--player-video-background`，播放页及舞台应使用 `background:var(--player-video-background,作品选定底色)`。不要把明亮彩色面板铺在视频周围。无需生成模拟视频或脚本。宿主在抉择/结局前退出视频全屏，动效不自行管理全屏或计时。

## 剧情地图：探索后才揭示

- 每个节点一个独立的 `data-node-ref="真实节点ID"` 区域；区域内只写一个 `data-node-label` 短名字（建议 2–8 汉字，最多 12），例如“深夜来信”，不能写剧情、结果或预告。可用同一区域的 jump 按钮回看；节点之间不要相互嵌套。
- 宿主只显示已访问节点和它们紧邻的未访问节点。首次游玩只出现入口的“？”；未访问节点显示“？”/灰色，不能点，连名字也不显示；它的后续节点和连线完全隐藏，不能用虚线框、编号或图例暗示总数。
- 每条连线独立标记 `data-map-from="源节点ID" data-map-to="目标节点ID"`，只连接已探索来源与可见目标。可以是独立 SVG 或其 g/path/line。不要把整幅网络画进一个 path，不要写无标记连线、节点编号、结局统计、CSS content/counter 标签。宿主会隐藏无来源标记的旧连线。
- 使用可收缩的 flex/grid 流式布局，让隐藏的未来节点不占位；不要 absolute 固定全部未来节点位置造成大片空洞。标题可写“你的足迹”，提示可写“走过的片段可以回看”。颜色、边框同时区分当前/已访问/未知状态，不单靠颜色。

## 抉择层 pattern

保持透明舞台，在画面下缘用局部渐变或轻薄底板承托问句与选择。问句简短，两选项可左右排列、窄屏上下排列；按钮文字优先，避免巨幅装饰挡住表情。保留输入指定的热点几何与权威 option label。仅通过 hover/focus/active、入场错峰提供轻微反馈；倒计时由宿主提供的变量驱动，不使用 CSS 动画假计时。

## 交付自查

首页能否让首次观众愿意点开始，且不知道后续结果？视频是否占据可用区域？未访问地图是否只露问号、未来后代是否不占位？结局是否只有“结局”？桌面 1280×720 与手机 390×640 的导航、全部选项是否能操作？只输出符合宿主安全协议的完整 HTML，不附解释、Markdown 或优化建议。编辑已有页面时保留未受影响内容；需要整体现代化时同时更新四页的视觉语言。
